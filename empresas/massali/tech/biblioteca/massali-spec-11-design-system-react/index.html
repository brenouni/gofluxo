SPEC-11 — Design system e layout React moderno e simples

Objetivo: interface clara, responsiva, consistente e rica em recursos úteis. React é a base de composição, não um catálogo pronto de widgets; bibliotecas e componentes próprios fornecem tabela, calendário, gráfico e outras interações. “Todos os recursos” significa cobertura dos padrões necessários às tarefas, sem instalar ou mostrar tudo ao mesmo tempo.

Features avançadas de grid não são prometidas como gratuitas: usar fallback documentado ou aprovar licença quando necessário.

Tokens são uma proposta estética, não evidência de contraste já aprovado. Design deve passar verificação em temas e estados. Claro como padrão, dark opcional e preferência por usuário; nenhuma troca muda dados.

Estrutura de aplicação

Desktop: sidebar de cerca de 240px recolhível, header de cerca de 64px, breadcrumb, título, descrição curta e ação principal. Conteúdo administrativo usa largura fluida, formulários com largura de leitura limitada. Mobile: menu em drawer, header compacto, título e ação reorganizados; não encolher uma tabela de 16 colunas para caber na tela.

Navegação: Visão geral; Operação (agendamentos/reclamações); Cadastros; Estoque; Financeiro; Remuneração; Relatórios; Administração (usuários/permissões/configurações/auditoria). Itens e ações respeitam permission. Seleção de concessionária só entre escopos autorizados e identificada como filtro/contexto, não troca de tenant.

Componentes padrão: AppShell, PageHeader, FilterBar, StatCard, StatusBadge, DataTable, EntityDrawer, FormSection, ConfirmDialog, EmptyState, ErrorState, Skeleton, NotificationCenter, AuditTimeline e FieldDiff.

Funções opcionais (Kanban, command palette e personalização avançada) entram após fluxo básico validado. Não acrescentar editor de texto rico, mapa, vídeo ou chat apenas porque há componente disponível; requisito real define sua inclusão.

Listagens e formulários

Uma ação principal por página, filtros frequentes visíveis e “Mais filtros” para os demais. Mostrar chips ativos, botão limpar e quantidade/total definido. Busca com debounce proposto 300ms, cancelar request obsoleta; respostas fora de ordem não substituem pesquisa recente.

Número/identidade, status e ação principal sempre visíveis por layout; colunas secundárias no detalhe. Sticky/pinning quando suportado pela biblioteca/edição; fallback layout compacto. Mobile oferece cards com número, cliente, prazo, status e detalhes; rolagem horizontal confinada ao relatório, nunca na página inteira.

Formulários agrupam Identificação, Agenda/Veículo, Itens/Valores e Observações. Label sempre visível; obrigatórios indicados; resumo de erro e foco no primeiro campo inválido. Valores em BRL com parsing seguro; lógica financeira oficial vem da API. Bloquear clique repetido durante submit, mas backend ainda garante idempotência. Concorrência 409 abre comparação/recarga, preservando entrada do usuário.

Nenhum toast “salvo” antes do commit. Não aplicar atualização otimista a pagamento, estorno, permissões ou transição com efeitos financeiros. Pode usar otimista em preferência visual reversível com rollback.

Complemento de paridade — LEG-024

A SPA do legado possui dashboard, relatórios e telas pessoais próprios. A existência na navegação não comprova seus filtros, fontes, cálculos ou autorização. Antes de implementar indicadores equivalentes, documentar fonte, período, escopo e fórmula; validar os totais contra os registros de origem. Telas devem explicitar filtros e estado de atualização, sem apresentar estimativas como valores conciliados. Rastreabilidade: SPEC-13. Inspeção funcional e aceite quantitativo desses relatórios permanecem pendentes.

Atualização do responsável em 07/10/2026: SPEC-19 define tamanhos 10/30/50/100/Todos, filtros/busca no banco e códigos sequenciais por contexto. Coluna ID usa codigo (PROD, AGEND, CLI conforme entidade); UUID técnico continua nos vínculos. Todos usa o conjunto autorizado e filtrado no banco, com virtualização no frontend quando necessário.

Primeira entrega visual: SPEC-21 e ADR-0013. MUI Table com janela de renderização atende Todos sem licença de grid; Storybook, tema escuro e novos módulos continuam pendentes. Prévia sintética separada da API real.
