Clientes finais — API v1

Base: /api/v1/customers. Autenticação por sessão; comandos exigem CSRF.

  • GET /: customers.read; search, nome, codigo, ativo, page (1), pageSize (10).

pageSize aceita 10, 30, 50, 100, todos (0), além dos valores compatíveis 1–100. Retorno: itens, total, pagina, tamanhoPagina. Todos exige página 1.

  • GET /{id}: customers.read; retorna um cliente autorizado ou 404.
  • POST /: retirado. Retorna 405; cadastro inicial deve ocorrer pelo agendamento (SPEC-22).
  • PATCH /{id}: customers.manage; corpo nome e versaoEsperada. Retorna 200.
  • POST /{id}/disable: customers.manage; corpo versaoEsperada. Retorna 204.

Cliente: id (UUID), codigo (CLI01 etc.), concessionariaId, nome, ativo, versao. UUID permanece nas rotas e relações; tabelas exibem codigo na coluna ID. Escopo indisponível retorna 404; validação 400; conflito de versão 409; permissão insuficiente 403. Não há exclusão física nem alteração do escopo.

Revisão de negócio em andamento: SPEC-22 define criação inicial pelo agendamento. O POST independente foi retirado do fluxo público. O contrato operacional futuro deve cadastrar pessoa e agendamento na mesma transação. Preservar clientes existentes.
