Contrato de auditoria v1 implementado

AuditEventV1 é serializado em JSON camelCase na outbox jsonb operacional. EventId é UUID estável entre retries; occurredAt é UTC. Campos monetários nas alterações usam strings decimais invariantes. Origin atual: Api; actorType: Human. Outcome admite Succeeded, Denied e Failed. Ações e campos fora da allowlist são rejeitados.

MóduloAções registradasCampos de alteração permitidos
AuditAudit.ReadNenhum campo de alteração
CatalogProduto.Created, Produto.Updated, Produto.DeactivatedNome, Tipo, PrecoUnitario, CustoUnitario, Ativo
IdentityAccessLogin.Succeeded/Failed, Session.Revoked, Password.ResetRequested/Reset/Changed, Mfa.SetupRequested/Enabled, User.Invited/RolesChanged/ScopesChanged/Disabled, Role.Created/PermissionsChanged, Bootstrap.Completed, Access.DeniedPerfis, Concessionarias, Permissoes, Ativo, Motivo

Senha, token de ativação, chave TOTP e código de recuperação não são campos de auditoria. Mutações de catálogo e seu evento são persistidos na mesma unidade de trabalho; acesso usa suas transações. Falha de persistência não autoriza sucesso.

Transporte implementado: exchange topic durable massali.audit.v1, routing key audit.operation.v1, fila durable massali.audit.ingest.v1, mensagem persistente, mandatory e publisher confirms. PublicadoEm só é gravado após confirmação. Dispatcher na API é habilitado por Audit:DispatcherEnabled; falha mantém outbox.

Escopo publicado: dealershipId. Eventos locais anteriores com concessionariaId são normalizados pelo dispatcher, mantendo EventId. Não são aceitos campos extras, schemaVersion desconhecido, ação/campo não registrado ou payload acima de 64 KiB.

Ingestão: EventosAuditoria na base dedicada guarda o evento validado, hash, concessionária e instantes. EventoId é chave global para deduplicação. Repetição idêntica não cria outra linha; mesmo ID com conteúdo diferente vai à quarentena. Ack somente após gravação/deduplicação. Falhas de persistência fecham a conexão, retornando mensagens sem ack à fila. InvalidAuditEventException causa republicação confirmada na fila durable massali.audit.quarantine.v1 antes do ack original.

Readiness do worker depende de acesso recente ao banco e à fila; liveness comprova somente processo. Quarentena exige revisão operacional; não há descarte automático.

Consulta autorizada de listagem/detalhe: contrato HTTP. API usa credencial SELECT distinta; cada leitura bem-sucedida registra Audit.Read na outbox.

Limites: exportação, consulta global, particionamento/retenção e integridade externa ainda pendentes. Contas de desenvolvimento não comprovam append-only de produção. Este recorte não comprova conformidade integral com a SPEC-10.

Decisões: ADR-0002 e ADR-0009. Clientes: Catalog / ClienteFinal / ClienteFinal.Created, ClienteFinal.Updated, ClienteFinal.Deactivated. Changes deve ser vazio; nomes pessoais não são copiados. Entidade, versão, ator e escopo seguem o envelope existente (ADR-0012).

Contexto opcional da requisição — 19/10/2026

request: actorName, login, ipAddress, browser, operatingSystem, device, userAgent, location, locationSource. Nome/login são snapshot do operador resolvido pelo servidor; não são os nomes de clientes ou texto de tentativa de login desconhecida. Limites: 160/256/64/80/80/80/512/200/80 caracteres respectivamente. Objeto nulo é omitido para preservar hashes V1. IP resolvido pelo proxy confiável; origem local DB-IP Lite quando disponível; geolocalização aproximada e User-Agent não comprovam presença física. Sem cookies, tokens, senha ou corpo HTTP. Consumidores devem ser atualizados antes de produtores. Ver SPEC-64 e ADR-0041.
