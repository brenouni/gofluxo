SPEC-03 — Contrato das Minimal APIs

Prefixo /api/v1; rotas agrupadas por módulo com MapGroup, tags e OpenAPI. Policy de autenticação como padrão; AllowAnonymous somente em rotas explicitamente públicas. Webhooks usam autenticação própria do provedor.

Rotas são contratos propostos; criação de handlers só após spec de cada caso Ready. Ações de pagar/settle nesta API representam registro interno da liquidação; transferência de dinheiro não integra o escopo base.

Entrada: DTOs separados por ação, validação de campos antes do service, validação de domínio dentro do caso; limite de tamanho e allowlist de campos de ordenação. GET paginado: page>=1; pageSize padrão 10; seletor 10/30/50/100/Todos conforme SPEC-19; modo Todos retorna o conjunto filtrado/autorizado sem corte oculto; ordenar por chave estável como tie-breaker. Filtros desconhecidos/estados inválidos retornam 400.

Saída: 201+Location para criação; 200 para consulta/comando com resultado; 204 quando sem corpo; 202+Location para solicitação assíncrona persistida; 400 validação; 401 sessão ausente/inválida; 403 ação negada; 404 inexistente ou recurso fora do escopo para não revelar existência; 409 concorrência/estado/idempotência; 429 limitação. Política de 403 versus 404 documentada e uniforme.

Erros: ProblemDetails com code estável, traceId e erros de campo; nenhum stack trace, SQL ou dado secreto. Exemplo: APPOINTMENT_INVALID_TRANSITION; RESOURCE_VERSION_CONFLICT; IDEMPOTENCY_PAYLOAD_MISMATCH; INSUFFICIENT_BALANCE.

Transição exemplo: POST /appointments/{id}/confirm contém expectedVersion, header Idempotency-Key e protection CSRF na sessão web. Resposta contém id, status, version e referências aos efeitos criados. Horário de confirmação vem do servidor.

WhatsApp exemplo: solicitar com tipo de destinatário e template autorizado, não telefone/mensagem livre do browser. Service resolve destinatário no escopo permitido. Retorna 202 com notificationId e status Pending, mesmo se broker estiver temporariamente indisponível após persistência local. Se banco não conseguir persistir, não retorna Accepted.

Aceite: OpenAPI corresponde às respostas reais; endpoint negado não executa service; 202 não afirma mensagem enviada; contratos e testes cobrem versionamento, erros, paginação e filtros.

Paginação, busca e IDs visíveis: SPEC-19. Listas de produtos, usuários e auditoria aplicam os filtros no banco antes de contar/paginar; codigo é o identificador visível e UUID permanece interno às rotas/vínculos.
