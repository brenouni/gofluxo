SPEC-01 — Arquitetura e Clean Code

Organizar cada camada por módulo: IdentityAccess, Catalog, Operations, Finance, Compensation, Inventory, Reporting, Integrations, Audit. API contém módulos de rotas, não um Program.cs com toda a aplicação.

Regras obrigatórias

  • Entidades de negócio, propriedades e métodos de domínio em português brasileiro, sem acentos nos identificadores (ex.: Produto, Concessionaria, PrecoUnitario). Repositories/services específicos acompanham o nome da entidade. Nomes de frameworks e camadas técnicas permanecem conforme suas APIs. Texto de interface pt-BR. Decisão atualizada por solicitação do usuário. Usar async/await e CancellationToken nas operações de I/O.
  • Endpoint não acessa DbContext, não calcula comissão e não publica diretamente no RabbitMQ.
  • Service autoriza recurso, coordena entidade/repositories e define transação. Não transforma invariantes da entidade em duplicação de lógica.
  • Entidade protege estado com métodos de intenção: Confirm, Complete, Cancel. Coleções não são alteráveis livremente pelo chamador.
  • Repository por agregado/caso de consulta; interfaces com intenção, como GetByIdAsync e GetForSettlementAsync. Evitar generic repository que apenas replica DbSet.
  • Não retornar IQueryable para API/Application nem expor entidades EF como resposta HTTP. Consultas de relatório usam projeções e query services próprios.
  • Salvar uma vez por unidade de trabalho. Repository não chama SaveChanges independentemente de uma operação composta.
  • Preferir composição; evitar service base gigante, helper genérico de negócio e interfaces sem necessidade de substituição/fronteira.
  • DTOs de criação/edição enumeram campos permitidos. Não usar binding direto de entidades nem permitir IsAdmin, PaidAmount ou Status arbitrário no payload.
  • Não capturar exceção e retornar sucesso. Falhas esperadas têm códigos de domínio; falhas inesperadas geram log correlacionado e resposta sanitizada.
  • Sem senhas, tokens, documentos integrais, telefone completo ou payload sensível em logs. Logs registram IDs e códigos técnicos.
  • Analisadores, formatação e nullable habilitados; build e testes críticos obrigatórios na revisão.

Padrão de caso de uso

Exemplo conceitual: ConfirmAppointmentEndpoint → IAppointmentService.ConfirmAsync → scoped IAppointmentRepository + Appointment.Confirm → criação dos efeitos locais definidos + OutboxMessage → IUnitOfWork.CommitAsync → resposta HTTP. O dispatcher envia a outbox depois do commit. Serviços locais que participam desse caso usam a mesma unidade de trabalho; não iniciam commits independentes.

Aceite: teste de arquitetura detecta dependência de Domain em infraestrutura; endpoint sem lógica financeira; uma alteração composta pode ser revertida integralmente; relatório não materializa tabelas inteiras para somar na memória.
