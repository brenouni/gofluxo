SPEC-00 — Condução e decisões

Objetivo: entregar fluxos de negócio completos e números conciliáveis.

Stack definida: ASP.NET Core/.NET 10 LTS, EF Core, PostgreSQL, React/TypeScript, RabbitMQ e workers .NET separados para WhatsApp e auditoria em base dedicada. Verificar patches e compatibilidade dos pacotes no início da implementação; fixar versões nos arquivos de dependência.

Organização: monólito modular para negócio e API; worker com implantação independente para integração externa. Uma empresa operadora e várias concessionárias no escopo base. Concessionária não equivale a empresa SaaS. Multiempresa exige revisão antes de criar tabelas e filtros de isolamento.

Decisão atualizada: entidades de negócio em PT-BR, com identificadores sem acentos. Toda execução e validação do projeto deve estar disponível em Docker: API, frontend quando implementado, workers, bancos, broker, migrations e testes. SDK/Node no host não são requisitos de execução.

Vocabulário: Entity = entidade de domínio; Repository = persistência orientada ao agregado; Service = coordenação de caso de uso; Endpoint = contrato HTTP e adaptação de entrada/saída. Clean Code é requisito de legibilidade e responsabilidade, não quantidade de camadas.

Fluxo de trabalho por spec: status Draft → Ready → InProgress → InReview → Accepted. Uma spec só fica Ready quando possui objetivo, contrato, regras, dependências, cenários e aceite. As specs abaixo estão Draft até revisão inicial, com decisões técnicas do usuário já incorporadas. Uma regra pendente bloqueia somente o caso de uso que depende dela.

Artefatos no repositório: docs/specs; docs/adr para decisões; docs/runbooks para operação; docs/contracts para HTTP/eventos; tests para verificação. ADRs iniciais: monólito modular; sessão web com Identity; transações/outbox; entrega de WhatsApp; política financeira; escopo por concessionária.

Atualização documental: specs originais permanecem em docs/specs/ por ADR-0001; PRD em docs/prd, ADRs indexados em docs/adr/README.md e evidências em SPEC-13. Toda percepção nova da inspeção deve atualizar a spec pertinente ou criar outra, conforme SPEC-18. Decisões normativas não são prova de comportamento do legado.
